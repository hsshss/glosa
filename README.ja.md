# Glosa

[English](README.md) | 日本語

対象音源の自動判別とポートマップの自動切り替えに対応したMIDIプレイヤーです。  
TMIDI Player の定義ファイルを利用した音源エミュレーション機能にも対応しています。

![メインウィンドウ。プレイリストに曲ごとに判別した対象音源が出て、液晶パネルに曲の文字とドット絵が出ています](images/main-window.png)

## 特徴

### できること

- **基本的なファイル形式に対応**
  - スタンダード MIDI ファイル（`.mid` `.midi` `.rmi`）
  - レコンポーザのファイル（`.rcp` `.r36` `.g18` `.g36`）
  - ZIP・LZH の書庫の中の曲を、展開せずにそのまま演奏できます
- **対象音源の自動判別** — ファイル名・タイトル・フォルダパス・添付テキストから、その曲がどの音源向けか（対象音源）を判別します。
  どの情報をどの順番で使うかは、環境設定で選べます。
  名前で分からないときは、曲の MIDI データからも判別します。
- **ポートマップ** — ポート A〜F の 6 本の出力に、それぞれ別の MIDI デバイスをつなげます。
  つなぎ方に名前を付けて複数持っておけ、曲の対象音源に合わせて自動で切り替えられます。
- **音色マップの自動切り替え** — 下位機種向けの曲を、その機種の音色マップで鳴らします。
  - 出力音源が SC-88 以降なら、SC-55・SC-88 などの曲を、その機種のマップで鳴らします。
  - 出力音源が MU100 以降なら、MU50・MU80・MU90 の曲を MU Basic で鳴らします。
- **代理発音（CTF）** — SC-55mkII 以降の Sound Canvas で、その機種に無い音色を SC-55 と同じく近い音色で鳴らします。
- **液晶パネル** — 音源の液晶表示（16 桁 × 2 行の文字と 16 × 16 のドット絵）を再現します。
  ドット絵が出ていないときはレベルメーターになります。
- **演奏モニタ** — パートごとの音色名・音量・パン・鍵盤・コード名を表示します。
- **タブ式のプレイリスト** — 複数のプレイリストをタブで開けます。
- シーク、キーボードのメディアキー、ファイルのドロップやファイルマネージャから開いたときの演奏開始に対応しています。

### TMIDI定義ファイルを利用するとできること

TMIDI Player の定義ファイルを読み込むと、TMIDI Player と同じ**音源エミュレーション**が使えます。
曲が書かれた音源と違う音源でも、その違いを変換して鳴らします（たとえば SC-88Pro 向けの曲を MU2000 で鳴らすなど）。

- **演奏中の変換** — 対象音源と出力音源の組み合わせごとに、定義ファイルの規則で曲を書き換えます。
  音色を出力音源にある音色へ置き換えたり、出力音源が受け付けないエクスクルーシブを止めたりします。
- **出力音源の選択肢が増えます** — 定義ファイルにしか無い音源（SYG20、MSGS など）も選べるようになります。
- **TMIDI Player と同じ規則での判別** — 環境設定で、対象音源の判別を定義ファイルの規則で行うように切り替えられます。

![SC-88Pro 向けの曲を MU2000 で鳴らしているところ。ステータスバーに、行っている変換が出ています](images/emulation.png)

## 動作環境

- Windows 10（1607 以降）・Windows 11、macOS 14 以降、Linux（x64・Arm64。Ubuntu 22.04・Debian 12・Fedora 42・RHEL 8 以降など）
- MIDI 出力デバイス（外部の MIDI 音源、ソフトウェア音源、仮想 MIDI ポート）
  - Windows では loopMIDI などの仮想 MIDI ポートが使えます。
  - macOS では「Audio MIDI 設定」の IAC ドライバや、ソフトウェア音源が作る仮想ポートが使えます。
  - Linux では ALSA シーケンサーのポート（USB の MIDI 機器、ソフトウェア音源が作るポート、Midi Through）が使えます。

.NET ランタイムは必要ありません（配布物に含まれています）。

## インストールとアンインストール

配布物は GitHub のリリースのページにあります。

- **Windows** — `glosa-<バージョン>-win-x64.zip`（ARM では `win-arm64`）を好きな場所に展開し、中の `glosa.exe` を実行します。
  中の `install.cmd` を実行すると、スタートメニューに Glosa が出て、MIDI・RCP ファイルの「プログラムから開く」で Glosa を選べるようになります。
  プログラムはその場から動かさず、登録だけをします（管理者の権限は要りません）。フォルダを移動したら、もう一度 `install.cmd` を実行してください。
  アンインストールは、`uninstall.cmd` で登録を解除してから、フォルダを削除します。
  - 署名がないため、初めて実行するときは「Windows によって PC が保護されました」と表示されます。**詳細情報** を押してから **実行** を押してください。`install.cmd` でセキュリティの警告が出たときも **実行** を押します。展開する前に zip ファイルのプロパティで「許可する」にチェックを入れておくと、どちらも出なくなります。
- **macOS** — `glosa-<バージョン>-osx-arm64.zip`（Intel の Mac では `osx-x64`）を展開し、`Glosa.app` をアプリケーションフォルダに入れます。
  アンインストールは `Glosa.app` をゴミ箱に入れます。
  - 初めて開くときは「開けません」と表示されます。**システム設定 → プライバシーとセキュリティ** の下にある「このまま開く」を押すと、次からは普通に開けます。
- **Linux** — `glosa-<バージョン>-linux-x64.tar.gz`（ARM では `linux-arm64`）を好きな場所に展開し、中の `install.sh` を端末から実行します。
  確認に `y` と答えると、アプリケーションの一覧に Glosa が出て、MIDI ファイルなどをファイルマネージャから Glosa で開けるようになります。
  端末を開かずに実行すると、確認に答えられないので何も登録されません。
  フォルダを移動したら、もう一度 `install.sh` を実行してください。
  アンインストールは、`uninstall.sh` で登録を解除してから、フォルダを削除します。

## 使い方

### 出力先を決める

**設定 → ポートマップ設定...** で、ポート A〜F に MIDI デバイスを割り当てます。

- **出力音源**には、そのポートの先につないでいる音源の機種を選びます。
  エミュレーションと、曲の前に送るリセットに使われます。
- **リセット**に印を付けたポートへは、曲の前に出力音源のリセット（GS Reset、XG System On など）を送ります。
- **ポートマップ**は複数作れます。機材ごとに作っておくと便利です。
  - いちばん上のマップは既定のマップです。消すことはできず、どのマップにも当てはまらない曲はこのマップで鳴ります。
  - マップに**対象音源**を登録しておくと、その音源向けの曲はそのマップで鳴ります。

どのマップを使うかは **設定 → ポートマップ** で選びます。「自動」なら曲ごとに対象音源から選び、マップを選べばそのマップに固定します。

<img src="images/port-map-settings.png" width="560" alt="ポートマップ設定。MU2000 のマップに、対象音源が MU2000・MU1000・MU128 の曲を割り当てています">

### 曲を追加して演奏する

- 曲は **ファイル** メニューか、ウィンドウへのドロップで追加します。
  書庫やフォルダを追加すると、中の曲がまとめて入ります。
- 曲をダブルクリックすると、その曲から演奏します。
- 曲順とリピートは **設定** メニューで選びます。
- キーボードのメディアキーでも操作できます。

### プレイリスト

- 複数のプレイリストをタブで開けます。
  タブや曲を右クリックすると、プレイリストや曲の操作が出ます。
- ほかの場所のプレイリストファイルは **ファイル → プレイリストを開く...** で開きます。

### 対象音源

プレイリストに、その曲がどの音源向けかが出ます。

- **括弧つき**（`(SC-88PRO)` など）は、自動で判別した値です。
- ファイルをまだ読んでいない曲は空欄です。演奏するか、環境設定の **曲の長さと対象音源を事前に調べる** を入れると出ます。
- 判別が違うときは、曲を選んで右クリックの **対象音源** から指定できます。

判別の規則は、`define.yaml` に書いてあります。調整するときは、設定フォルダ（**設定 → 設定フォルダを開く**）の `define.override.yaml.sample` を `define.override.yaml` という名前に変えて書き換えます。Glosa は `define.yaml` の代わりにそちらを読み込みます。`define.yaml` は新しいバージョンに入れ替えると上書きされるので、書き換えないでください。
書き方は `docs` フォルダの [define.ja.md](src/Glosa.App/docs/define.ja.md) を見てください。

### TMIDI定義ファイル

TMIDI定義ファイルは **設定 → TMIDI定義ファイルを開く...** で読み込みます。
TMIDI定義ファイルは本ソフトウェアに含まれていません。TMIDI Player からエクスポートしたものを利用してください。

### 画面

- **ウィンドウ → 演奏モニタ...** で、パートごとの状態を表示します。
- **ウィンドウ → デバッグ...** に、読み込めなかったファイルなどのメッセージが記録されます。

<img src="images/monitor.png" width="640" alt="演奏モニタ。パートごとの音色・音量・パン・発音数・鍵盤と、上にコード名が出ています">

### 環境設定

**設定 → 環境設定...** で変えられます。変更は即座に、または次の曲から反映されます（言語と画面の描画方法だけは次の起動から）。

## コマンドライン

曲やフォルダのパスを渡すと、表示中のプレイリストに追加されます。
ドロップしたときと同じく、演奏も一時停止もしていなければ、追加した曲の先頭から演奏を始めます。

Glosa はひとつしか起動しません。
すでに起動していれば、新しく起動した Glosa は受け取ったパスとオプションを起動中の Glosa に渡してすぐに終わり、起動中の Glosa のウィンドウが前に出ます。
`--config` で設定フォルダを分けた Glosa は、別のものとして同時に起動できます。

```
glosa [オプション] [曲やフォルダ...]
```

| オプション | 内容 |
|---|---|
| `--def <file>` | TMIDI定義ファイルを読み込む |
| `--use <module>` | 出力音源。設定に残る |
| `--target <module>` | 対象音源。同じコマンドラインで渡した曲に付く |
| `--device <番号または名前の一部>` | ポート A の出力デバイス。手で選んだポートマップ、なければ既定のマップに入り、設定に残る |
| `--config <folder>` | 設定とプレイリストを置くフォルダ |

## 設定の保存場所

設定とプレイリストは次の場所に保存されます。**設定 → 設定フォルダを開く** で開けます。

```
Windows        %APPDATA%\glosa\
Linux / macOS  ~/.config/glosa/
```

- `settings.yaml` — 設定
- `playlists\*.yaml` — プレイリスト（1 つにつき 1 ファイル）

`--config` を付けて起動すると、代わりにそのフォルダを使います。
